# PROYECTO 7: E-Commerce Microservice - Product Catalog

## FASE
Produccion & Ecosistema

## DESCRIPCION
Microservicio productivo de catalogo de productos con todas las caracteristicas de un sistema enterprise: API REST, cache, observabilidad, CI/CD, containerizacion, documentacion OpenAPI y despliegue cloud-ready.

## OBJETIVOS FUNCIONALES

### Funcionalidades core:

**CRUD de productos:**
- Crear, leer, actualizar, eliminar productos
- Campos: SKU, nombre, descripcion, precio, stock, categorias, imagenes, atributos dinamicos
- Variantes de productos (ej: tallas, colores)
- Inventario con tracking de stock
- Categorias jerarquicas con navegacion

**Busqueda y filtros:**
- Busqueda full-text por nombre/descripcion
- Filtros: precio (rango), categoria, disponibilidad, rating
- Ordenamiento: precio, popularidad, fecha creacion
- Paginacion optimizada
- Faceted search (agregaciones por categoria, precio, etc)

**Cache y performance:**
- Cache de productos frecuentes (Redis o Caffeine)
- Cache invalidation strategy
- Respuestas HTTP con ETags para cache del cliente
- Rate limiting por IP/API key

**Integracion con otros servicios:**
- Event publishing (Kafka/RabbitMQ) cuando producto cambia
- Consumir eventos de inventario
- API para servicio de recomendaciones
- Webhook notifications para cambios de precio

### Requisitos tecnicos:

**Observabilidad:**
- Logs estructurados (JSON) con correlation IDs
- Metricas: request rate, latency percentiles, error rate, cache hit ratio
- Distributed tracing (OpenTelemetry o Zipkin)
- Health checks (/health, /ready)
- Prometheus metrics endpoint

**Seguridad:**
- Autenticacion JWT
- Autorizacion basada en roles (ADMIN, USER)
- Rate limiting
- Input validation y sanitization
- OWASP Top 10 compliance

**DevOps:**
- Dockerfile multi-stage optimizado
- Docker Compose para ambiente local
- GitHub Actions pipeline: build, test, security scan, deploy
- Kubernetes manifests (deployment, service, ingress)
- Helm chart (opcional)
- Environment-specific configs (dev, staging, prod)

**Documentacion:**
- OpenAPI 3.0 spec (Swagger UI)
- README completo con arquitectura
- ADRs (Architecture Decision Records)
- Runbook para operaciones
