# PROYECTO 8: Distributed Task Scheduler

## FASE
Produccion & Ecosistema

## DESCRIPCION
Sistema distribuido de scheduling de tareas con coordinacion entre multiples nodos, persistencia, tolerancia a fallos, balanceo de carga y observabilidad completa. Arquitectura inspirada en sistemas como Quartz Scheduler pero simplificada.

## OBJETIVOS FUNCIONALES

### Funcionalidades core:

**Scheduling de tareas:**
- Registrar tareas programadas (cron expressions)
- Ejecucion unica o recurrente
- Tareas con parametros configurables
- Prioridad de tareas
- Timeout configurable por tarea
- Retry policy con backoff exponencial
- Dead letter queue para tareas fallidas

**Distribucion y alta disponibilidad:**
- Multiples nodos workers ejecutando en paralelo
- Coordinacion via base de datos (optimistic locking) o Zookeeper/etcd
- Distribucion automatica de carga entre nodos
- Failover: si nodo muere, otro retoma sus tareas
- Split-brain prevention
- Cluster membership tracking

**Monitoreo y control:**
- Dashboard web: tareas activas, completadas, fallidas
- Pausar/reanudar tareas
- Ejecutar tarea manualmente (trigger)
- Ver historial de ejecuciones
- Metricas por tarea: tiempo promedio, tasa de exito/fallo
- Alertas si tarea falla N veces consecutivas

**Persistencia:**
- Estado de tareas en base de datos
- Logs de ejecuciones con resultado y stacktrace
- Snapshots de estado del cluster

### Requisitos tecnicos:

**Arquitectura:**
- Scheduler service (REST API + worker threads)
- Worker nodes que consumen tareas de cola
- Service discovery (Eureka, Consul o DNS)
- Shared database o distributed lock (Redis, Zookeeper)

**Concurrencia:**
- Lock-free algorithms donde posible
- Pessimistic/Optimistic locking para coordinacion
- Thread pools configurables por nodo
- Graceful shutdown con drain de tareas activas

**Observabilidad:**
- Metricas: tareas ejecutadas/min, latencia, errores
- Distributed tracing para debugging
- Structured logging con contexto de tarea
- Health checks avanzados (liveness, readiness, cluster status)

**DevOps:**
- Kubernetes deployment con 3+ replicas
- Horizontal Pod Autoscaler basado en metricas custom
- ConfigMaps y Secrets para configuracion
- StatefulSet o Deployment segun diseño
- Service mesh (Istio/Linkerd) para observabilidad (opcional)
- Helm chart completo

**Testing:**
- Unit tests con alta cobertura
- Integration tests con Testcontainers
- Chaos engineering: matar nodos aleatoriamente
- Load testing: 1000+ tareas concurrentes
