# PROYECTO 3: REST API - Library Management System

## FASE
Backend & Data

## DESCRIPCION
API REST completa para gestion de biblioteca con operaciones CRUD, relaciones entre entidades, validaciones y persistencia en base de datos relacional.

## OBJETIVOS FUNCIONALES

### Entidades principales:
- Books: ISBN, titulo, autor, editorial, anio, categoria, disponible
- Users: ID, nombre, email, fecha registro, tipo (estudiante/profesor)
- Loans: ID, libro, usuario, fecha prestamo, fecha devolucion, estado

### Endpoints requeridos:

**Books:**
- POST /api/books - Crear libro
- GET /api/books - Listar todos (con paginacion y filtros)
- GET /api/books/{id} - Obtener por ID
- PUT /api/books/{id} - Actualizar libro
- DELETE /api/books/{id} - Eliminar libro
- GET /api/books/search?query=... - Buscar por titulo/autor

**Users:**
- POST /api/users - Registrar usuario
- GET /api/users - Listar usuarios
- GET /api/users/{id} - Obtener usuario
- PUT /api/users/{id} - Actualizar usuario
- GET /api/users/{id}/loans - Historial de prestamos

**Loans:**
- POST /api/loans - Crear prestamo
- GET /api/loans - Listar prestamos activos
- PUT /api/loans/{id}/return - Devolver libro
- GET /api/loans/overdue - Prestamos vencidos

### Requisitos tecnicos:
- Framework: Spring Boot o Jakarta EE
- Base de datos: PostgreSQL o MySQL
- ORM: JPA/Hibernate
- Validaciones: Bean Validation
- Manejo de errores consistente (formato estandar de respuesta)
- Logging de operaciones
- Tests de integracion con base de datos en memoria

### Reglas de negocio:
- Usuario no puede tener mas de 3 prestamos activos simultaneos
- No se puede prestar libro no disponible
- Prestamo maximo: 14 dias (estudiantes), 30 dias (profesores)
- ISBN debe ser valido
- Email debe ser unico
