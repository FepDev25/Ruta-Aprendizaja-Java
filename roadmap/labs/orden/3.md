# LAB 3: Memory Leak Detection & Analysis

## DURACION ESTIMADA
3 horas

## OBJETIVO
Crear programas con diferentes tipos de memory leaks, detectarlos con herramientas, analizar causas y aplicar soluciones.

## TAREAS

### Parte 1: Crear Memory Leaks Intencionalmente
Implementar programas con los siguientes leaks:

**Leak 1: Collection sin limpiar**
- HashMap que acumula objetos sin remover
- Simular cache sin eviction policy

**Leak 2: Listeners no removidos**
- Event listeners registrados pero nunca desregistrados
- Observer pattern mal implementado

**Leak 3: ThreadLocal sin cleanup**
- ThreadLocal que retiene objetos grandes
- Thread pool reutilizando threads

**Leak 4: Static references**
- Colecciones estaticas que crecen indefinidamente
- Singleton reteniendo referencias

**Leak 5: Classloader leak**
- Webapp reload sin cleanup de recursos
- ClassLoader no liberado por referencias estaticas

### Parte 2: Deteccion con Herramientas
Para cada leak:
- Ejecutar con monitoring de memoria
- Detectar sintomas: heap creciendo constantemente
- Generar heap dump cuando memoria alta
- Analizar con VisualVM o Eclipse MAT
- Identificar leak suspect usando dominator tree
- Encontrar GC root path que retiene objetos

### Parte 3: Reference Types
- Experimentar con Strong, Soft, Weak, Phantom references
- Implementar cache con WeakHashMap
- Implementar cache con SoftReferences
- Comparar comportamiento bajo presion de memoria
- Usar ReferenceQueue para cleanup

### Parte 4: Soluciones
- Aplicar fix a cada leak
- Validar con profiler que leak desaparecio
- Documentar patron y solucion

## ENTREGABLES
- Codigo de cada leak scenario
- Scripts de deteccion
- findings.md con:
  - Screenshots de heap dumps mostrando leak
  - Analisis de GC roots
  - Comparacion de reference types
  - Catalogo de patrones de leaks y como evitarlos
  - Checklist de prevencion
