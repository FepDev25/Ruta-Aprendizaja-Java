# LAB 2: Garbage Collector Comparison & Tuning

## DURACION ESTIMADA
4 horas

## OBJETIVO
Experimentar con diferentes garbage collectors, analizar comportamiento, generar heap dumps, y encontrar configuracion optima para diferentes workloads.

## TAREAS

### Parte 1: Benchmark Base
- Crear programa que genera diferentes patrones de carga de memoria:
  - Short-lived objects (muchos objetos efimeros)
  - Long-lived objects (objetos que sobreviven multiples GCs)
  - Mixed workload
  - Memory leak simulado
- Instrumentar con metricas: throughput, latencia, pause times

### Parte 2: Comparacion de Collectors
Ejecutar benchmark con cada collector y documentar metricas:
- Serial GC (-XX:+UseSerialGC)
- Parallel GC (-XX:+UseParallelGC)
- G1 GC (-XX:+UseG1GC)
- ZGC (-XX:+UseZGC) - si disponible en JDK
- Shenandoah (-XX:+UseShenandoahGC) - si disponible

Medir para cada uno:
- Tiempo total de ejecucion
- Pause times (max, avg, p99)
- Throughput
- CPU usage
- Memory footprint

### Parte 3: GC Logs Analysis
- Habilitar GC logging detallado
- Analizar logs con herramientas (GCViewer, GCEasy)
- Identificar:
  - Young GC vs Full GC frequency
  - Promotion rate
  - Object allocation rate
  - Pause time distribution

### Parte 4: Heap Dump Analysis
- Generar heap dump con jmap
- Analizar con VisualVM o Eclipse MAT
- Identificar:
  - Top memory consumers
  - Objetos retenidos
  - Leak suspects
  - Dominador tree

### Parte 5: Tuning Ejercicio
- Dado workload especifico, encontrar configuracion optima de:
  - Heap size (-Xmx, -Xms)
  - Young generation size (-Xmn)
  - GC threads
  - Pause time goals (G1: -XX:MaxGCPauseMillis)
- Documentar decisiones y trade-offs

## ENTREGABLES
- Scripts de benchmark
- findings.md con:
  - Tabla comparativa de collectors
  - Graficos de pause times y throughput
  - Analisis de heap dumps
  - Recomendaciones por tipo de workload
  - Flags de tuning optimos encontrados
