# LAB 11: Java Platform Module System (JPMS)

## DURACION ESTIMADA
3-4 horas

## OBJETIVO
Dominar el sistema de modulos de Java 9+, crear aplicaciones modulares, entender strong encapsulation y migrar codigo legacy.

## TAREAS

### Parte 1: Module Basics
- Crear primer modulo con module-info.java
- Declaraciones: module, requires, exports
- Compilar modulo
- Ejecutar aplicacion modular
- Modular JAR vs classpath JAR

### Parte 2: Module Dependencies
Crear aplicacion multi-modulo:
- modulo.core: funcionalidad base
- modulo.api: interfaces publicas
- modulo.impl: implementacion (no exportada)
- modulo.app: aplicacion principal

Experimentar con:
- requires: dependencia normal
- requires transitive: dependencia transitiva
- exports: paquetes publicos
- exports...to: export calificado (solo a modulos especificos)

### Parte 3: Services & ServiceLoader
- Definir service interface en un modulo
- Implementar service provider en otro modulo
- Usar provides...with y uses en module-info
- Cargar implementaciones con ServiceLoader
- Multiples providers del mismo servicio
- Plugin architecture con JPMS

### Parte 4: Strong Encapsulation
- Internal APIs no accesibles sin exports
- Reflection sobre modulos: setAccessible bloqueado
- Abrir modulos para reflection: opens, open module
- --add-opens para emergencias

Casos:
- Intentar acceder a internal API (error)
- Framework que necesita reflection (Spring, Hibernate)

### Parte 5: Migrating to Modules
Migrar aplicacion classpath a modulos:
- Bottom-up migration: libraries primero
- Top-down migration: aplicacion primero
- Automatic modules: JARs sin module-info en module path
- Unnamed module: codigo en classpath

Problemas comunes:
- Split packages (mismo paquete en multiples modulos)
- Cyclic dependencies
- Missing dependencies

### Parte 6: jlink - Custom Runtime Images
- Crear runtime image minimo con jlink
- Incluir solo modulos necesarios
- Reducir tamano de distribucion
- Launcher scripts custom
- Comparar tamano: JRE completo vs custom runtime

### Parte 7: jdeps - Dependency Analysis
- Analizar dependencias de aplicacion
- Detectar internal APIs usage
- Generar module-info.java automaticamente
- Identificar modulos JDK requeridos

### Parte 8: Module Path vs Classpath
- Comparar comportamiento
- Module path: strong encapsulation, explicit dependencies
- Classpath: todo accesible, implicit dependencies
- Interoperabilidad: mix de modulos y classpath
