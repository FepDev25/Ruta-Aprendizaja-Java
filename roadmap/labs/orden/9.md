# LAB 9: JVM Profiling Tools Deep Dive

## DURACION ESTIMADA
4 horas

## OBJETIVO
Dominar herramientas de profiling para diagnosticar problemas de performance: CPU hotspots, memory leaks, thread contention.

## TAREAS

### Parte 1: VisualVM
- Conectar a aplicacion local y remota
- Monitorear en tiempo real: CPU, memoria, threads, clases
- CPU profiling: identificar metodos hot
- Memory profiling: analizar heap, generaciones
- Thread profiling: detectar deadlocks, contention
- Generar heap dump y analizar
- MBeans monitoring
- Plugins: BTrace, Coherence, etc.

### Parte 2: Async Profiler
- Configurar async-profiler (low overhead)
- Generar flame graphs de CPU
- Generar flame graphs de allocations
- Comparar con VisualVM profiler (overhead)
- Interpretar flame graphs: identificar bottlenecks
- Profiling en produccion sin impacto

### Parte 3: Java Flight Recorder (JFR)
- Habilitar JFR (flags o jcmd)
- Grabar sesion de profiling
- Analizar .jfr file con JDK Mission Control
- Eventos capturados: GC, compilacion, I/O, excepciones
- Crear custom events de aplicacion
- Continuous recording para diagnostico post-mortem

### Parte 4: Command-Line Tools
Experimentar con:
- jps: listar procesos Java
- jstat: estadisticas de JVM (GC, compiler)
- jmap: heap dump, histogram
- jstack: thread dump, detectar deadlocks
- jcmd: comando multiproposito
- jinfo: flags de JVM en runtime
- Scripting para monitoreo automatizado

### Parte 5: Profiling Escenarios Reales
Crear aplicaciones con problemas y diagnosticar:

**Escenario 1: CPU alto**
- Aplicacion con loop infinito en background thread
- Detectar con profiler cual metodo consume CPU

**Escenario 2: Memory leak**
- Cache sin eviction creciendo indefinidamente
- Generar heap dump y encontrar leak

**Escenario 3: Thread contention**
- Multiples threads compitiendo por mismo lock
- Identificar con thread profiler
- Medir wait time vs run time

**Escenario 4: Excessive GC**
- Aplicacion generando objetos muy rapido
- Analizar con jstat o JFR
- Optimizar para reducir allocation rate

**Escenario 5: Slow I/O**
- Operaciones de disco lentas bloqueando threads
- Detectar con JFR file I/O events

### Parte 6: Production Profiling
- Habilitar profiling sin restart (jcmd)
- Minimizar overhead
- Safe points y bias
- Interpretar resultados en sistema bajo carga

## ENTREGABLES
- Aplicaciones de prueba con problemas
- Scripts de diagnostico
- findings.md con:
  - Guia de cada herramienta con screenshots
  - Flame graphs analizados
  - Comparacion de overhead: VisualVM vs Async vs JFR
  - Casos de uso: cuando usar cada herramienta
  - Checklist de diagnostico por sintoma
  - Comandos de referencia rapida
